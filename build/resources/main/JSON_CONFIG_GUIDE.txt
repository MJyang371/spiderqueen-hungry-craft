【0】这个文件是什么（必读）
中文：
  这是一份「纯说明文档」。本 mod 的任何代码都不会读取它：它不参与注册、不参与数据包或资源
  包的解析、不占用任何 id、也不进任何注册表。因此：
    · 留在 jar 里：对游戏没有任何影响。
    · 直接删掉：游戏照常运行。
    · 它不可能因为「没被移除」而导致游戏崩溃。
  它的唯一用途：让整合包作者与服主不必反编译，就能修改本 mod 的数值、规则、掉落与外观。
  本文件的位置：
    · jar 内部：JSON_CONFIG_GUIDE.txt（jar 根目录）
    · jar 旁边：build/libs/spiderqueen_hungrycraft_JSON_CONFIG_GUIDE.txt（免解压查看）

English:
  This is a documentation-only file. No code of this mod ever reads it: it takes part
  in no registry, in no datapack or resourcepack parsing, claims no id, and never
  enters a registry. Therefore:
    · Keeping it inside the jar: zero effect on the game.
    · Deleting it: the game runs exactly the same.
    · It can never crash the game by being left in place.
  Its only purpose is to let modpack authors and server owners change the numbers,
  rules, drops and looks of this mod without decompiling anything.
  Where it lives:
    · Inside the jar: JSON_CONFIG_GUIDE.txt (jar root)
    · Next to the jar: build/libs/spiderqueen_hungrycraft_JSON_CONFIG_GUIDE.txt

【1】快速开始 / Quick start
--------------------------------------------------------------------------------
中文：
  1) 两种包，改的东西不同：
     · 数据包(datapack)：改「规则 / 数值 / 掉落 / 标签 / 维度 / 伤害类型」，路径在 data/ 下。
     · 资源包(resourcepack)：改「贴图 / 模型 / 语言 / 粒子 / 音效」，路径在 assets/ 下。
  2) 覆盖 mod 内置 json 的推荐做法：在你的包里放「完全相同的路径」。例如要改巨蛛真身调参，
     就在数据包里新建：
       data/spiderqueen_hungrycraft/queen_beast/tuning.json
     数据包的优先级高于 mod 内置资源，所以你的文件会整体替换掉 mod 的文件。
  3) 数据包放在：<存档目录>/datapacks/<你的包名>/ ，并且必须带 pack.mcmeta
     （1.20.1 的 pack_format = 15）。世界内执行 /reload 即可生效，不必重启。
  4) 写错了不会崩：无法识别的方块/实体/物品 id 会被跳过，并在日志里留一行 warn，
     本次修改不生效，但世界和游戏继续正常运行。改之前请先备份原文件。
  5) 需要重启的情况：维度与维度类型（dynamic registry 内容）改动后，需要退出重进世界
     或重启游戏；纯客户端资源（模型/语言）建议按 F3+T 重载或重启客户端。

English:
  1) Two kinds of packs, two kinds of data:
     · Datapack: rules, numbers, loot, tags, dimensions, damage types. Lives under data/.
     · Resourcepack: textures, models, language, particles, sounds. Lives under assets/.
  2) Recommended way to override a built-in json: ship the exact same path in your pack.
     To retune the Queen Beast, create:
       data/spiderqueen_hungrycraft/queen_beast/tuning.json
     Datapacks have a higher priority than built-in mod resources, so your file simply
     replaces the file of the mod.
  3) Put datapacks in <world>/datapacks/<your_pack>/ and give it a pack.mcmeta
     (pack_format = 15 on 1.20.1). Run /reload inside the world; no restart needed.
  4) A typo cannot crash anything: unknown block/entity/item ids are skipped with one
     warning line in the log, that one change does nothing, and the game keeps running.
     Always back up the original file first.
  5) A restart is needed for dimensions and dimension types (dynamic registry content):
     leave and re-enter the world or restart the game. Client resources (models,
     language) are best reloaded with F3+T or a client restart.

【3】领地核心 / Territory Core
--------------------------------------------------------------------------------
中文：
  3.1 效果：放下领地核心后，以它所在的「区块段(section, 16x16x16)」为中心，压制 3x3x3 个
      区块段（即 48x48x48 格）内的「自然刷新」。只拦自然刷新：刷怪蛋、/summon、刷怪笼、
      繁殖、结构生成、事件生成全部照常。它不清除已有生物，也不阻挡生物走进来。
      右键它会给右键者本人显示该范围 5 秒（穿墙可见）。用任何工具挖它都恒定 60 秒。
  3.2 可以用 json 改的部分：
      · 合成配方 data/spiderqueen_hungrycraft/recipes/territory_core.json
        默认：8 个 minecraft:string + 1 个 #minecraft:beds（任意颜色的床都算）。
        改法：把 key 换成别的物品/tag id，或改 pattern 与字母映射；整份替换也可以。
      · 掉落 data/spiderqueen_hungrycraft/loot_tables/blocks/territory_core.json
        默认：挖掉掉自己。可改成掉别的物品或加数量。
      · 外观 assets/spiderqueen_hungrycraft/blockstates/territory_core.json 与
        assets/spiderqueen_hungrycraft/models/block/territory_core.json
        默认是 cube_all + minecraft:block/cobweb 贴图，并带 "render_type": "cutout"。
        资源包可以换成自己的模型/贴图；render_type 也可用 cutout_mipped 或 solid。
      · 名称与提示 assets/spiderqueen_hungrycraft/lang/zh_cn.json 与 en_us.json，
        相关键：block.spiderqueen_hungrycraft.territory_core、
        message.spiderqueen_hungrycraft.territory_range_shown。
  3.3 不能用 json 改的部分（写在代码里，整合包改不了）：
      · 范围大小与形状：3x3x3 区块段 = 48x48x48，按区块段对齐。
      · 挖掘恒定 1/1200 每 tick = 60 秒，与工具、效率附魔无关。
      · 只取消 MobSpawnType.NATURAL 这一个原因。
      · 右键范围显示 5 秒（100 tick）、发光等级 10、末影风格粒子。

English:
  3.1 Effect: once placed, the core uses the chunk section (16x16x16) it sits in as the
      centre and suppresses NATURAL spawns inside 3x3x3 sections (48x48x48 blocks).
      Only natural spawns are blocked: spawn eggs, /summon, spawners, breeding,
      structure spawns and event spawns all keep working. It never removes existing
      mobs and never blocks mobs from walking in. Right click shows that box to the
      clicking player for 5 seconds (visible through walls). Mining it always takes
      exactly 60 seconds, with any tool.
  3.2 What you CAN change with json:
      · Recipe: data/spiderqueen_hungrycraft/recipes/territory_core.json
        Default: 8x minecraft:string + 1x #minecraft:beds (any bed colour counts).
        Change the key ids, or the pattern and its letters.
      · Loot: data/spiderqueen_hungrycraft/loot_tables/blocks/territory_core.json
        Default: it drops itself. You may change the item or the count.
      · Looks: assets/spiderqueen_hungrycraft/blockstates/territory_core.json and
        assets/spiderqueen_hungrycraft/models/block/territory_core.json
        Default: cube_all with the minecraft:block/cobweb texture and
        "render_type": "cutout". A resource pack may swap model and texture;
        render_type also accepts cutout_mipped or solid.
      · Names: assets/spiderqueen_hungrycraft/lang/zh_cn.json and en_us.json, keys
        block.spiderqueen_hungrycraft.territory_core and
        message.spiderqueen_hungrycraft.territory_range_shown.
  3.3 What json can NOT change (fixed in code):
      · The size and shape of the box: 3x3x3 sections = 48x48x48, section aligned.
      · The constant 1/1200 per tick mining speed = 60 seconds, ignoring tool and
        Efficiency.
      · That only MobSpawnType.NATURAL is denied.
      · The 5 second (100 tick) range display, the light level 10 and the
        enderman style particles.

【4-E】Queen Beast tuning (English)
--------------------------------------------------------------------------------
  File: data/spiderqueen_hungrycraft/queen_beast/tuning.json
  · Read by the server only. /reload applies it at once, and the armour of a player
    who is already transformed is recalculated immediately.
  · Every key is optional: only write what you want to change, everything else keeps
    the built-in default, which is exactly the value shown in the shipped file.
  · Any number of files may exist: they are parsed in alphabetical resource id order
    and a later file overrides an earlier one. Overriding the same path is the easy
    way. A file in your own namespace only wins if that namespace sorts after
    spiderqueen_hungrycraft (for example zz_).
  · Keys, defaults and clamps in brackets:
      armor_bonus                        30.0   extra armour in beast form
      bite.width / height / depth        3.0 / 2.0 / 2.0   bite hit volume (min 0.5)
      camera.bite_shake.duration_ticks   8      bite camera punch length (1~40)
      camera.bite_shake.pitch_degrees    3.5    pitch peak in degrees
      camera.bite_shake.yaw_degrees      1.2    yaw peak in degrees
      camera.bite_shake.roll_degrees     0.55   roll peak in degrees
      camera.bite_shake.fov_degrees      3.0    fov pull in degrees
      jump.max_charge_ticks              20     charge limit (1~60)
      jump.minimum_stomp_charge          0.35   below this no stomp happens
      jump.min_vertical_velocity         0.55   slowest take off
      jump.max_vertical_velocity         1.05   fastest take off
      jump.forward_velocity              0.22   forward speed of a jump
      stomp.damage                       15.0   landing damage (max 200)
      stomp.radius                       4.0    stomp radius (0.5~12)
      stomp.vertical_range               2.5    stomp vertical range
      stomp.knock_up                     0.9    upward knock
      stomp.knock_outward                0.35   outward knock
      stomp.camera.duration_ticks        10     stomp camera punch length (1~40)
      stomp.camera.pitch/yaw/roll/fov    5.0 / 1.5 / 0.7 / 4.0   stomp camera axes
      charge.speed                       0.85   charge speed (0.1~3.0)
      charge.food_interval_ticks         20     ticks between two food costs (1~600)
      charge.food_cost_per_interval      1      food points per cost (0~20)
      charge.damage                      20.0   charge damage (max 200)
      charge.knock_up                    0.8    upward knock of a charge
      charge.knock_forward               1.0    forward push of a charge
      charge.max_turn_degrees_per_tick   3.0    turning limit per tick in degrees
      charge.hard_impact_explosion_power 4.0    explosion power on a hard impact (0~16)
      block_breaking.<profile>.<key>      see section 5
  · Break rule priority, fixed in code, strongest first:
      1) a block in protected_blocks / protected_tags is never broken,
      2) a block with hardness below 0 (bedrock and friends) is never broken,
      3) a block with a block entity is only broken when allow_block_entities is true,
      4) a block listed in allow_blocks / allow_tags is broken even above the limit,
      5) everything else is judged by max_hardness (<=) or, when hardness_reference is
         given, by strictly less than the hardness of that block.
  · Outside of the tuning file (fixed in code): damage types, models and animations,
    the HUD, the keys and the charge sounds.

【5】巨蛛真身破坏方块规则 / Beast block breaking rules
--------------------------------------------------------------------------------
中文：
  位置：tuning.json 里的 "block_breaking" 段，共 4 个档位，分别对应四种能力：
    · transform_clearance  变形清场（变身瞬间清出空间）
    · body_crush           走路压碎（普通行走压碎的小障碍）
    · stomp                落地踩踏
    · charge               高速冲撞
  每档可写的键（都可选，缺省沿用内置默认）：
    max_hardness           硬度上限，<= 该值可破坏（默认：各档不同，见随包文件）
    hardness_reference     方块 id；写了它就改用「该方块硬度」当上限（严格小于）。
                           例如 "minecraft:obsidian" 让冲撞只能撞碎比黑曜石软的东西。
                           写了这一项时 max_hardness 不再生效。
    drop_blocks            破坏时是否掉落物品（默认 false = 直接消失）
    allow_block_entities   是否允许破坏带方块实体的方块，如箱子/机器（默认 false）
    allow_blocks           方块 id 列表，显式允许，会越过硬度上限
    allow_tags             方块标签列表，显式允许，会越过硬度上限
    protected_blocks       方块 id 列表，永不破坏（最高优先级）
    protected_tags         方块标签列表，永不破坏（默认含 #spiderqueen_hungrycraft:beast_protected）
  随包默认值（节选）：
    transform_clearance  max_hardness 3.0，allow_tags：logs / planks / leaves / beast_fragile
    body_crush           max_hardness 0.2，allow_tags：logs / leaves / beast_fragile
    stomp                max_hardness 1.0，allow_tags：dirt / logs / leaves / beast_fragile
    charge               hardness_reference minecraft:obsidian，drop_blocks true，
                         allow_block_entities true
  提示：想「让巨蛛能拆任何东西但保住主城」，就把 protected_tags 指向你自己写的标签，
  再把 protected_blocks 加上特定方块；想「让巨蛛连黑曜石都能撞碎」，把 charge 档的
  hardness_reference 换成更硬的方块（例如 minecraft:bedrock 会让它几乎无敌，慎用）。

English:
  Location: the "block_breaking" section of tuning.json. Four profiles, one per ability:
    · transform_clearance  clears a space while transforming
    · body_crush           crushes small obstacles while simply walking
    · stomp                the landing stomp
    · charge               the high speed charge
  Keys of every profile (all optional, missing keeps the built-in default):
    max_hardness           hardness limit, <= this value may be broken
    hardness_reference     a block id; when present, that block's hardness is the limit
                           (strictly less). Example: "minecraft:obsidian" makes a charge
                           break everything softer than obsidian. max_hardness is then
                           ignored.
    drop_blocks            whether broken blocks drop items (default false, meaning the
                           blocks simply vanish)
    allow_block_entities   whether blocks with a block entity (chests, machines) may be
                           broken (default false)
    allow_blocks           list of block ids that are always allowed, above the limit
    allow_tags             list of block tags that are always allowed, above the limit
    protected_blocks       list of block ids that are never broken (highest priority)
    protected_tags         list of block tags that are never broken (default includes
                           #spiderqueen_hungrycraft:beast_protected)
  Shipped defaults (excerpt):
    transform_clearance  max_hardness 3.0, allow_tags logs / planks / leaves / beast_fragile
    body_crush           max_hardness 0.2, allow_tags logs / leaves / beast_fragile
    stomp                max_hardness 1.0, allow_tags dirt / logs / leaves / beast_fragile
    charge               hardness_reference minecraft:obsidian, drop_blocks true,
                         allow_block_entities true
  Tips: to let the beast dig through everything while keeping your base safe, point
  protected_tags at a tag of your own and add the specific blocks to protected_blocks.
  To let a charge break obsidian as well, switch the charge profile's
  hardness_reference to a harder block (minecraft:bedrock makes it almost unstoppable,
  use with care).

        Default: fog, sky and water colours, the mood sound minecraft:ambient.cave, an
        empty feature list and empty spawner lists. Effect: the Stomach biome spawns

        exhaustion 0.1 adds hunger cost on hit, scaling is
        when_caused_by_living_non_player.

        a stomach. Defaults: exhaustion 0, scaling never.

      bypasses_shield.

  8.4 Beast attack set (data/spiderqueen_hungrycraft/tags/damage_type/beast_attacks.json)

【9】标签手册（中文）/ Tag handbook (English in section 9-E)
--------------------------------------------------------------------------------
所有标签都在你自己的数据包里用同名路径覆盖，写法都是标准原版标签格式：
  { "replace": false, "values": [ "minecraft:cobweb", "#minecraft:logs",
    { "id": "一些mod:方块", "required": false } ] }
  · replace: false → 追加（默认）；replace: true → 整体替换掉 mod 的默认内容。
  · required: false → 该条目/模组不存在时不报错（跨模组兼容必用）。

A. 方块标签 data/spiderqueen_hungrycraft/tags/blocks/
   1) web_blocks       视为"蛛网"的方块。默认：cobweb + 三种女王蛛网 + 蜘蛛床。
                       效果：女王在其中按蛛网规则移动；女王挖掉时掉落 4~6 个线
                       （蜘蛛床例外，它的掉落表不变）。把方块加进来即可让女王
                       "把该方块当网处理"。
   2) beast_fragile    巨蛛顺手撕碎的方块。默认：玻璃系/树叶/花草/作物/cobweb/
                       藤蔓/火把/灯笼/干草块/脚手架等。
                       效果：被打碎时不看硬度上限（tuning 的 allow_tags 默认引用它）。
   3) beast_protected  巨蛛永不破坏的方块。默认：基岩/屏障/光源/命令方块/结构方块/
                       传送门/强化深板岩/刷怪笼/紫水晶母岩等。
                       效果：任何能力都不会破坏它（tuning 的 protected_tags 默认引用它）。
   4) spider_bed_frame 蜘蛛床仪式的 16 个框架方块。默认 #minecraft:logs（任意原木）。
                       效果：5x5 的仪式框架换材料（例如石头墙基）；清空该标签 =
                       仪式无法成立（也就做不出蜘蛛床）。

B. 实体标签 data/spiderqueen_hungrycraft/tags/entity_types/
   1) spider_like       蜘蛛类。默认：蜘蛛、洞穴蜘蛛。
                        效果：免疫蛛网效果、永不可被捕获；也被 web_immune 默认引用。
   2) web_immune        完全无视"蛛丝缠绕(Webbed)"。默认：#spiderqueen_hungrycraft:spider_like。
                        效果：把任意生物加进来，它就免疫蛛丝缠绕的减速与层数。
   3) uncapturable      永不可被捕获。默认：末影龙、凋零、监守者、远古守卫者。
   4) force_capturable  让"不是 Mob 的 LivingEntity"也能被捕获的白名单。默认：空。
   5) neutral_to_spider_queen        平时不主动攻击蜘蛛女王。默认：僵尸/尸壳/溺尸/
                        僵尸村民/骷髅/流浪者/苦力怕/蜘蛛/洞穴蜘蛛。
   6) always_hostile_to_spider_queen 即使在上面的名单里也永远敌对。默认：女巫/掠夺者/
                        卫道士/唤魔者/劫掠兽/幻术师/恼鬼/猪灵/猪灵蛮兵/疣猪兽/
                        远古守卫者/监守者/凋零/末影龙。
   7) village_defenders 会被授权主动猎杀女王的"村庄武力"。默认：铁傀儡，
                        以及可选的 guardvillagers:guard、irons_spellbooks:priest
                        （required:false，没装也不报错）。普通村民不会变成士兵。
   8) 阵营标签（同时命中多个时优先级：no_faction > queen_faction > human_faction >
      village_faction > illager_faction > nether_fortress_faction > piglin_faction >
      monster_faction > 无阵营）：
        human_faction            站在人类一边（默认：chad_steve 与三种战备 Steve、人类战斗员）
        village_faction          站在村庄一边（默认：村民、铁傀儡、流浪商人、可选 guardvillagers:guard）
        illager_faction          灾厄村民阵营（默认：女巫、掠夺者、卫道士、唤魔者、幻术师、劫掠兽、恼鬼）。
                                 对女王 / 人类 / 村庄敌对
        nether_fortress_faction  下界堡垒阵营（默认：烈焰人、恶魂、凋灵骷髅、岩浆怪）。
                                 对女王 / 人类 / 村庄敌对
        piglin_faction           猪灵生态阵营（默认：猪灵、猪灵蛮兵、僵尸猪灵、疣猪兽、僵尸疣猪兽）。
                                 对本 mod 阵营只对女王中立，其余一律不表态（PASS_THROUGH），
                                 一切交给它们自己的原版 AI
        monster_faction          主世界常规怪物（默认：僵尸系、骷髅系、蜘蛛系、苦力怕、史莱姆、
                                 末影人 / 末影螨、蠹虫）。注意：它不是"所有继承 Monster 的生物"
        queen_faction            女王一方（默认空，预留给未来的"虫群"）
        no_faction               完全没有阵营，不参与任何阵营逻辑（默认空）
      注意 1：玩家永远不由标签决定阵营，而由"蜘蛛女王能力"决定。
      注意 2：没有被任何阵营标签点名的怪物（监守者、凋零、末影龙、潜影贝、守卫者、远古守卫者、
              幻翼，以及其它模组的怪物）默认没有任何阵营，本 mod 不替它们决定要不要打女王，
              它们自己的原版 AI 也不会被本 mod 阻止。
      注意 3：人类与村庄守卫仍然会把"没有阵营的常规敌对怪物"（原版或其它模组的 Monster /
              MobCategory.MONSTER）当敌人，但 no_faction 里的实体除外。
      注意 4：always_hostile_to_spider_queen 只是 monster_faction 的修饰标签：把某个
              monster_faction 里的生物放进去，它才主动敌对女王。illager_faction 与
              nether_fortress_faction 天然敌对，不需要这个标签；piglin_faction 永远中立。
   9) 女王阵营（queen_faction）与女王虫群（Queen Colony）是两层，不要混：
        - queen_faction 是【静态阵营标签】：表示"蜘蛛女王体系"这一大类。永远不要为每个
          玩家做动态阵营（不要 queen_faction_<uuid> 之类），不要在运行时改 JSON，
          FactionId 永远是静态大类。
        - OwnerUUID / ColonyId 是【动态归属】：ColonyId = 该单位所属蜘蛛女王的 UUID。
          * 蜘蛛女王玩家：ColonyId = 该玩家自己的 UUID
          * 蜘蛛小弟（实现 QueenOwnedEntity 的单位，如小鬼蜘蛛 / 子嗣蜘蛛）：
            ColonyId = 它的 OwnerUUID
          * 其它实体：完全没有 ColonyId
        - 只有同一个 ColonyId 才算友军（QueenColonyRelations.isSameColony /
          isQueenSideFriendly）。
        - 不同 ColonyId 的 Queen 方单位：本框架既不判友军、也不判敌人，
          以后由 PvP / 女王权杖 / 仇恨状态 / 服务器规则决定。
        - 所以 queen_faction 内部【不是】"永远全部互为友军"：矩阵里 QUEEN vs QUEEN 是
          PASS_THROUGH（不表态），友军判断交给 Colony 层。
      以后把一个小蜘蛛接入女王阵营时，必须同时满足：
        1) 加入 #spiderqueen_hungrycraft:spider_like
        2) 加入 #spiderqueen_hungrycraft:queen_faction
        3) 实体自身保存 OwnerUUID
        4) 实现接口 spiderqueenhungrycraft.faction.QueenOwnedEntity#getQueenOwnerUUID
      现在的小鬼蜘蛛 / 子嗣蜘蛛已经保存 OwnerUUID（NBT 键 MinionOwner）并实现了该接口，
      但本轮【没有】把它们放进 queen_faction（它们目前仍是"无阵营"）。
      重要：加入 queen_faction 不代表"所有小蜘蛛互为友军"——只有同 OwnerUUID 才是友军。

C. 物品标签 data/spiderqueen_hungrycraft/tags/items/

【9-E】Tag handbook (English)
--------------------------------------------------------------------------------
Override any tag with the same path in your own datapack. All of them use the vanilla
format:
  { "replace": false, "values": [ "minecraft:cobweb", "#minecraft:logs",
    { "id": "some_mod:block", "required": false } ] }
  · replace: false appends (default), replace: true replaces the whole list of the mod.
  · required: false keeps a missing mod from breaking the tag.

A. Block tags, data/spiderqueen_hungrycraft/tags/blocks/
   1) web_blocks       Blocks treated as webs. Default: cobweb, the three queen webs and
                       the spider bed. Effect: the queen moves in them by web rules, and
                       when she breaks one it drops 4~6 string (the spider bed is
                       excluded, its own loot table stays). Add a block to treat it as a
                       web as well.
   2) beast_fragile    Blocks the beast tears off easily. Default: glass family, leaves,
                       flowers, crops, cobweb, vines, torches, lanterns, hay, scaffolding.
                       Effect: broken without asking the hardness limit (the tuning file
                       references this tag in allow_tags).
   3) beast_protected  Blocks the beast never breaks. Default: bedrock, barrier, light,
                       command blocks, structure blocks, portals, reinforced deepslate,
                       spawner, budding amethyst. Effect: no ability can break them
                       (referenced by protected_tags in the tuning file).
   4) spider_bed_frame The 16 frame blocks of the spider bed ritual. Default
                       #minecraft:logs. Effect: change what the 5x5 frame is made of; an
                       empty tag means the ritual can never be built, so no spider bed.

B. Entity tags, data/spiderqueen_hungrycraft/tags/entity_types/
   1) spider_like       Spiders. Default: spider, cave spider. Effect: immune to the Webbed
                        effect and never capturable; also referenced by web_immune.
   2) web_immune        Ignores the Webbed effect entirely. Default: the spider_like tag.
                        Add any creature to make it immune to web slowing and stacks.
   3) uncapturable     Never capturable. Default: ender dragon, wither, warden, elder
                        guardian.
   4) force_capturable Opt in for living entities that do not extend Mob. Default: empty.
   5) neutral_to_spider_queen         Does not attack the Spider Queen on its own.
                        Default: zombie, husk, drowned, zombie villager, skeleton, stray,
                        creeper, spider, cave spider.
   6) always_hostile_to_spider_queen  Stays hostile even when listed above. Default:
                        witch, pillager, vindicator, evoker, ravager, illusioner, vex,
                        piglin, piglin brute, hoglin, elder guardian, warden, wither,
                        ender dragon.
   7) village_defenders The fighting part of a village, allowed to hunt the queen.
                        Default: iron golem plus the optional guardvillagers:guard and
                        irons_spellbooks:priest (required:false). A plain villager never
                        becomes a soldier.
   8) The faction tags. When a type matches several, the priority is
      no_faction > queen_faction > human_faction > village_faction > illager_faction >
      nether_fortress_faction > piglin_faction > monster_faction > no faction at all:
        human_faction            Chad Steve, the three prepared Steves, the human combatant
        village_faction          villagers, iron golems, wandering traders, optional guards
        illager_faction          the raiders (witch, pillager, vindicator, evoker, illusioner,
                                 ravager, vex); hostile to the queen, humans and villages
        nether_fortress_faction  blaze, ghast, wither skeleton, magma cube; hostile to the queen,
                                 humans and villages
        piglin_faction           piglin, piglin brute, zombified piglin, hoglin, zoglin; neutral
                                 towards the queen and pass through everywhere else, so their own
                                 vanilla AI keeps deciding every fight of theirs
        monster_faction          the ordinary overworld monsters (zombies, skeletons, spiders,
                                 creeper, slime, enderman, endermite, silverfish). Note that this
                                 is not "everything that extends Monster"
        queen_faction            empty by default, reserved for a future brood
        no_faction               no faction at all, takes part in nothing (empty by default)
      Note 1: the player is never classified by a tag; the queen capability decides that.
      Note 2: a monster that no faction tag names (warden, wither, ender dragon, shulker, guardian,
              elder guardian, phantom, every mob of another mod) has no faction at all, so this mod
              never decides for it whether it fights the queen and never suppresses its own AI.
      Note 3: humans and village defenders still treat an unaffiliated hostile monster of the vanilla
              game or of another mod (Monster or MobCategory.MONSTER) as an enemy - unless the type
              is in no_faction.
      Note 4: always_hostile_to_spider_queen is only a modifier of monster_faction: put a
              monster_faction entry into it and that creature hunts the queen. The illager and nether
              fortress factions are hostile on their own and never need it, and the piglin ecology
              stays neutral no matter what.
   9) The queen faction (queen_faction) and the queen colony (Queen Colony) are two layers:
        - queen_faction is the STATIC faction tag: the Spider Queen system as a whole. Never make
          a dynamic faction per player (no queen_faction_<uuid>), never rewrite the JSON at
          runtime: FactionId stays a fixed list of big categories.
        - OwnerUUID / ColonyId is the DYNAMIC belonging: the colony of a creature is the UUID of
          its Spider Queen.
          * Spider Queen player: ColonyId = that player's own UUID
          * Spider minion (anything implementing QueenOwnedEntity, e.g. imp spider / brood
            spider): ColonyId = its OwnerUUID
          * anything else: no ColonyId at all
        - Only the same ColonyId is friendly (QueenColonyRelations.isSameColony /
          isQueenSideFriendly).
        - Two queen side entities of different colonies are neither friends nor enemies here:
          that verdict is left to PvP rules, the future queen sceptre, the revenge memory or a
          server rule.
        - The inside of queen_faction is therefore NOT "always all friendly": QUEEN vs QUEEN is
          PASS_THROUGH in the matrix, and the colony layer answers who is a friend.
      Wiring a new spider into the queen side always needs all four of:
        1) it is in #spiderqueen_hungrycraft:spider_like
        2) it is in #spiderqueen_hungrycraft:queen_faction
        3) the entity stores an OwnerUUID itself
        4) it implements spiderqueenhungrycraft.faction.QueenOwnedEntity#getQueenOwnerUUID
      The current imp spider / brood spider already store the owner (NBT key MinionOwner) and
      already implement that interface, but this round did NOT put them into queen_faction: they
      are still without a faction. And being in queen_faction never means "all minions are
      friends" - only the same owner UUID is.

C. Item tags, data/spiderqueen_hungrycraft/tags/items/
   1) poison_web_trigger_foods  Food that triggers the poison web empowerment.
      Default: pufferfish, poisonous potato, spider eye. Add more to empower on them too.

D. Damage type tags: see section 8.4 (beast_attacks).

10.1 方块掉落表（data/spiderqueen_hungrycraft/loot_tables/blocks/，共 5 个）

                            全局修改器替换成 4~6 个线；普通玩家挖就是什么都没有。）
    · fire_queen_web.json   默认：1 个 minecraft:string（带 survives_explosion 条件）
    · poison_queen_web.json 默认：同火焰蛛网

    · territory_core.json   默认：掉落领地核心本身（带 survives_explosion）。

      "rolls": 1.0 且 entries 里用 "type": "minecraft:item", "name": "minecraft:string",
      functions: [ { "function": "minecraft:set_count",

10.2 全局战利品修改器（女王采网）
    · data/spiderqueen_hungrycraft/loot_modifiers/queen_web_harvest.json
      内容只有 type 与 conditions。效果：当蜘蛛女王破坏 #spiderqueen_hungrycraft:web_blocks

    · data/forge/loot_modifiers/global_loot_modifiers.json 只是把上面那个修改器登记进
      全局列表（Forge 会合并各家的同名文件）。一般不需要动它；如果动了，务必保留
      "replace": false，以免把其它模组的全局修改器一起抹掉。
10.3 资源包侧（assets/spiderqueen_hungrycraft/，只影响外观与文本，不影响平衡）
    · lang/zh_cn.json、lang/en_us.json：所有名称与提示。想加一门语言就新增

    · blockstates/*.json、models/block/*.json、models/item/*.json：方块/物品外观。

    · sounds.json：音效定义。默认只有 stomach_rumble（用本 mod 自带的 ogg，stream: true）。

10.4 灵魂容器规则（Soul Consumable round，data/spiderqueen_hungrycraft/soul_loot/，共 3 个文件）
    · container_weights.json：每个容器开出几个灵魂的权重，0~4 共五项。
        "count_weights": [2, 38, 30, 20, 10]      ← 依次是 0/1/2/3/4 个的权重
      默认：98% 的容器至少有 1 个，平均约 1.98 个。把某个数字改成 0 就等于那个数量不可能出现；
      写成 [100, 0, 0, 0, 0] 等于整个功能关闭（不用改代码）。
    · structure_families.json：canonical 家族表。每条写 family（十五种之一）、soul（这个家族给
      哪种灵魂）、structures（结构 ID 列表）、structure_tags（结构标签）。家族是「这个结构是
      什么」而不是「它在哪里」：丛林版本的下界要塞仍然是 nether_fortress，末地版本的矿井仍然
      是 mineshaft。家族在文件中的先后顺序就是重叠时的优先级——写在越前面越优先。
    · loot_tables.json：战利品表别名 + 拒绝表。别名有三种用法：
        1) 没有结构能认领这个容器时，由它来定家族（例如 minecraft:chests/simple_dungeon
           → dungeon：怪物房不是注册结构，只能靠战利品表认出来）；
        2) 与结构给出的家族一致时，用它细分档位（村庄 smith、沉船 treasure、堡垒 treasure）；
        3) 与结构给出的家族不一致时完全忽略——结构永远优先。
      ignored_loot_tables 里的表永远不给灵魂，即使它所在的结构会给（默认列了丛林神庙发射器
      与 Repurposed Structures 的 dispenser 系列）。
    · 三个文件会合并（按文件名排序，后写的覆盖同名键），所以整合包只要新增一个
      soul_loot/xxx.json 就能给别的结构模组加别名，不必复制本 mod 的文件。
    · 判定顺序：结构上下文 → family，战利品表只负责细分或补漏，最后由 family 给灵魂。一个容器
      最多追加 ONE 个 ItemStack（数量 1~4），绝不会占掉多个格子。
    · 兼容全部是可选的：repurposed_structures:* 与 better*:* 只是字符串，没装那些模组时永远
      匹配不到——游戏照常启动、照常跑 GameTest、原版箱子照常刷新。

10.2 The global loot modifier (queen web harvest)
    · data/spiderqueen_hungrycraft/loot_modifiers/queen_web_harvest.json holds only a

      #spiderqueen_hungrycraft:web_blocks (the spider bed excluded), the vanilla drops

    · The amount 4~6 is hardcoded; what you can change are the conditions. Adding
        { "condition": "minecraft:random_chance", "chance": 0.0 }

    · data/forge/loot_modifiers/global_loot_modifiers.json only registers that modifier

      to touch it; if you do, keep "replace": false so the modifiers of other mods

    · lang/zh_cn.json and lang/en_us.json: every name and message. To add a language,

    · blockstates/*.json, models/block/*.json, models/item/*.json: the looks. Spawn egg
      items use minecraft:item/template_spawn_egg by default; their egg colours are
      defined in code and cannot be changed by json.
    · particles/*.json: the texture list of a particle. Default: the vanilla
      minecraft:generic_0..7. Point it at your own textures and ship those PNGs.
    · sounds.json: the sound definitions. Default: only stomach_rumble, using the ogg of
      this mod with stream: true. You may change volume, pitch,
      attenuation_distance or point it at your own file.
    · Texture paths: textures/block/spider_bed.png, textures/item/cocoon.png,
      textures/entity/chad_steve.png, textures/entity/cocoon.png,
      textures/gui/beast_vision_overlay.png, textures/mob_effect/day_vision.png,
      textures/mob_effect/light_sensitivity.png.

      minecraft:block/cobweb texture and ship no PNG of their own; to change their look,
      override the blockstate and model in a resource pack and point them at your own
      texture.

10.4 The soul container rule book (Soul Consumable round, data/spiderqueen_hungrycraft/soul_loot/, 3 files)
    · container_weights.json holds the weights of how many lumps a container may hold, from 0
      to 4:
        "count_weights": [2, 38, 30, 20, 10]      <- the weight of 0/1/2/3/4 pieces
      Default: 98% of the containers hold at least one piece, about 1.98 pieces on average.
      Put a 0 on a count to make that count impossible; [100, 0, 0, 0, 0] turns the whole
      feature off without touching code.
    · structure_families.json holds the canonical families. Each entry names the family (one
      of the fifteen), the soul that family pays, its structure ids and its structure tags.
      A family is what a structure IS and not where it stands: a jungle fortress is still a
      nether fortress, an end mineshaft is still a mineshaft. The order of the families is
      the priority when two structures cover the same container - the earlier one wins.
    · loot_tables.json holds the loot table aliases and the refused tables. An alias is
      read three ways:
        1) as the family, when no structure owns the container (minecraft:chests/
           simple_dungeon -> dungeon, because a monster room is not a registered structure);
        2) as a sub type, when it belongs to the family the structure named (a village smith,
           a shipwreck treasure, a bastion treasure);
        3) never, when it belongs to another family - the structure always wins.
      ignored_loot_tables never hold a soul even inside a structure that pays (the dispenser
      of a jungle temple and the dispensers of Repurposed Structures are listed there).
    · The three files are merged in the order of their names (a later file wins per key), so
      a pack adds an alias for another structure mod by shipping its own soul_loot/xxx.json -
      it never has to copy the files of this mod.
    · Resolution order: the structure context names the family, the loot table then sharpens
      or names it, and the family pays one soul. A container is ever given at most ONE
      ItemStack of 1..4 pieces, so this mod never costs a container more than one slot.
    · The compatibility is optional: the repurposed_structures:* and better*:* names are
      plain strings, so a world without those mods starts, plays, runs its game tests and
      fills its vanilla chests exactly as it did before.

  · Territory Core: the 3x3x3 section box, the constant 60 second mining time, that only
    natural spawns are denied, the 5 second range display and the light level 10.

    condition, never change the amount.

    remaining fire and air, attributes and modifiers, potion effects, equipment and drop chances,
    inventory, villager trades and experience, tamed owner, tags, memories and other mods'
    capability data. All of it is put back when the silk is cut open.
  · Cutting a cocoon open: right click a cocoon with shears (any player, queen or not) - the cocoon is
    destroyed, the prey is let out exactly as it was, the shears lose 1 durability (none in creative
    mode) and a ring of vanilla cobweb break particles bursts around the silk. A creature that can no
    longer be built (the mod that added it was removed) refuses the cut and keeps the cocoon.
  · Stomach: the generated inner rooms, the HUD, the sound relay, the teleport and
    swallow / spit flow and the damage link rules.
  · Light Sensitivity: only at light level 12 or higher; nothing for the first two minutes,
    then weakness I (2 min), weakness II (4 min), slowness I (5 min), nausea (7 min)
    and blindness (10 min). Stepping into a darker place or drinking the potion of day
    vision clears all of it and restarts the countdown; creative and spectator players
    are never touched; none of these effects show particles.
  · Brewing: the Awkward Potion + Glow Ink Sac recipe of the Day Vision potion is
    registered in code.
  · Models, animations, keys, particle logic and the network packet layout (the protocol
    version changes with the mod version).

【13-E】Troubleshooting (English)
--------------------------------------------------------------------------------
  1) Nothing happened at all:
     · Is the datapack in <world>/datapacks/<pack>/ with a pack.mcmeta
       (pack_format = 15)?
     · Does the path match the table in section 2 exactly (namespace, folders, file)?
     · Did you run /reload? Is there an error in the log?
     · Dimensions and dimension types need a world re-enter or a game restart.
  2) Only part of it worked:
     · An unknown id (block / entity / item / tag) is skipped with one warning and the
       rest keeps working. Search the log for: Ignoring unknown block, unknown entity,
       invalid block tag.
  3) Log lines worth knowing:
     · "Applied N beast tuning file(s)"
     · "No beast tuning file found, using the built in defaults"
     · lines starting with "[Loadout]" and "[Spawn]"
  4) A look did not change:
     · Is the resource pack enabled? Press F3+T or restart the client, and check that the
       texture path really matches the one referenced inside the model.
  5) A gameplay value did not change:
     · Some values live in the Forge config file (section 11), others are hardcoded in
       Java (section 12).
  6) Multiplayer: client and server must run the same mod version (the protocol version
     has to match). Server side values apply to every player.
